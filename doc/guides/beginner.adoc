== Beginners Guide

This guide installs an Oracle AI Database 26ai with a container database `DB1` and the PDB `ORCLPDB`
on an Oracle Linux 9 VM with `ansible-oracle`.

=== Overview

==== Architecture overview
:puml: http://www.plantuml.com/plantuml/proxy?src=https://raw.githubusercontent.com/oravirt/ansible-oracle/master/doc

image::{puml}/guides/beginner.puml[Architecture]

==== What are we going to do?

. Prepare the Ansible controller: Ansible in Ubuntu on WSL2 on Windows.
. Configure the inventory with the IP address and login user of the Oracle Linux 9 VM.
. Start the playbook `playbooks/do_all.yml`. It executes all needed playbooks:
.. `opitzconsulting.ansible_oracle.os`: prepare the VM for AutoUpgrade
.. `playbooks/autoupgrade.yml`: install AutoUpgrade on the VM and download a _gold image_ from My Oracle Support.
   The gold image is a complete ORACLE_HOME including the Release Update.
.. `opitzconsulting.ansible_oracle.single_instance_fs`: configure the OS, install the ORACLE_HOME from the gold image
   and create the database.

=== Requirements

==== Oracle Linux 9 VM

The VM is not created by this guide.
A description for the creation of the VM with Hyper-V follows later.

.Requirements for the VM
[options="header"]
|=======================
|Item |Requirement
|Operating system |Oracle Linux 9 x86_64
|CPU |2 vCPUs (recommended)
|Memory |8 GB RAM (recommended)
|Disk |`/dev/sda` with the volume group `ol` on `/dev/sda3`.
The volume group needs min. 81 GB free space for swap (16 GB), `/u01` (40 GB) and `/u02` (25 GB).
See `host_fs_layout` in `group_vars/all/host.yml`.
|Network |Fixed IP address, reachable from the Ansible controller with SSH
|Internet |Access to the Oracle Linux yum repositories and to My Oracle Support for AutoUpgrade
(`updates.oracle.com`, `login-ext.identity.oraclecloud.com`, `aru-akam.oracle.com`)
|Login user |User with SSH login and `sudo` privileges, e.g. `ol`
|=======================

==== Ansible controller

This guide uses Ubuntu on WSL2 on Windows as Ansible controller.

NOTE: Optionally, the database VM can be used as Ansible controller as well.
Install the packages with `dnf` instead of `apt` in this case,
e.g. `sudo dnf install -y git python3`.
`ansible_host` and `ansible_user` in the inventory are used the same way,
the VM connects to itself with SSH.

.Requirements for the Ansible controller
[options="header"]
|=======================
|Item |Requirement
|Python |Python 3 with `venv`
|Ansible |`ansible-core` >= 2.16
|Internet |Access to GitHub and Ansible Galaxy
|=======================

AutoUpgrade is executed on the VM, not on the Ansible controller.
Java and the gold image are not needed on the Ansible controller.

==== My Oracle Support

A My Oracle Support account is needed for the download of the gold image.

=== Setup Ansible controller

IMPORTANT: All steps are executed on the Ansible controller.

.Install packages
----
sudo apt update
sudo apt install -y git python3-venv
----

.Create a Python virtual environment with Ansible
----
python3 -m venv ~/venv/ansible-oracle
source ~/venv/ansible-oracle/bin/activate

pip install ansible-core
----

IMPORTANT: Activate the virtual environment in each new shell with `source ~/venv/ansible-oracle/bin/activate`.

.Clone git repository
----
mkdir -p ~/git
cd ~/git

git clone https://github.com/oravirt/ansible-oracle.git
----

.Install collections
----
cd ~/git/ansible-oracle/example/beginner/ansible
ansible-galaxy collection install -r requirements.yml
----

=== Configure inventory

==== IP address and login user

The VM is configured in `inventory/hosts.yml`.
Change `ansible_host` and `ansible_user` for your VM.

.inventory/hosts.yml
----
---
all:
  children:
    dbfs:
      hosts:
        beginner-dbfs:
          # IP address or DNS name of the Oracle Linux 9 VM
          ansible_host: 192.168.66.161
          # Login user on the VM with sudo privileges (SSH key login)
          ansible_user: ol
----

NOTE: `beginner-dbfs` is only the name of the host in the inventory.
The host specific variables are in `inventory/host_vars/beginner-dbfs/`.
Rename the directory as well, when you change the name.

==== SSH key

Ansible connects with an SSH key to the VM.

.Create SSH key (skip it, when a key exists already)
----
ssh-keygen -t ed25519
----

.Copy the public key to the VM
----
ssh-copy-id ol@192.168.66.161
----

==== Check the connection

.Connection test
----
cd ~/git/ansible-oracle/example/beginner/ansible
ansible all -m ansible.builtin.ping
----

.Test of sudo
----
ansible all -b -m ansible.builtin.command -a id
----

TIP: Add `--ask-become-pass` (`-K`) to all `ansible` and `ansible-playbook` commands,
when `sudo` requires a password for the login user.

==== My Oracle Support credentials

The My Oracle Support credentials are read from the environment variables `MOS_USERNAME` and `MOS_PASSWORD`.

.My Oracle Support credentials
----
export MOS_USERNAME=<your My Oracle Support login>
read -s MOS_PASSWORD && export MOS_PASSWORD
----

Alternatively, store the credentials in the file `.env` in the working directory
and load it into the shell before starting `ansible-playbook`.

.~/git/ansible-oracle/example/beginner/ansible/.env
----
MOS_USERNAME=<your My Oracle Support login>
MOS_PASSWORD=<your My Oracle Support password>
----

.Load .env into the shell
----
cd ~/git/ansible-oracle/example/beginner/ansible
set -a; . ./.env; set +a
----

IMPORTANT: `.env` contains your password. Restrict the permissions with `chmod 600 .env`. +
The file is ignored by git (`.gitignore`).

NOTE: The lookups are defined in `inventory/group_vars/all/mos_login.yml`. Optionally, set `mos_username` and `mos_password` there statically
instead of the environment variables. Encrypt the password with `ansible-vault` in this case.

==== Database passwords

The password for all database users is `default_dbpass` in `inventory/group_vars/all/password.yml`.

WARNING: The default `Oracle_123` is for test environments only. Change it and use `ansible-vault` for other environments.

=== AutoUpgrade on the VM

AutoUpgrade is executed on the VM (`autoupgrade_run_local: false` in `inventory/group_vars/all/autoupgrade.yml`).
It downloads the gold image directly into `/u01/sw` on the VM.
No installation media are copied from the Ansible controller (`oracle_sw_copy: false`).

The execution of AutoUpgrade on the VM requires:

- the Python module `pexpect` for the keystore with the My Oracle Support credentials,
- a JDK for `autoupgrade.jar` and
- the download directory `/u01/sw` on the filesystem `/u01`.

The playbook `os` creates the filesystem `/u01` (`host_fs_layout` in the inventory).
`playbooks/autoupgrade.yml` installs the packages for the JDK and `pexpect` before the installation of AutoUpgrade.
Therefore `do_all.yml` executes the playbook `os` before AutoUpgrade.
The playbook `os` is executed a second time, because it is a fixed part of
`opitzconsulting.ansible_oracle.single_instance_fs`.
The second execution changes nothing.

.Download configuration in inventory/group_vars/all/autoupgrade.yml
[options="header"]
|=======================
|Variable |Value |Description
|`autoupgrade_download_latest` |`true` |Download the latest `autoupgrade.jar` from Oracle
|`autoupgrade_download_patches` |`target_version: 26`, `patch: RECOMMENDED`, `gold_image: ALL` |Gold image for 26ai with all recommended patches
|`autoupgrade_download_gold_image_rename` |`true` |Rename the gold image to `db_home_<release>.zip`, e.g. `db_home_26.04.zip`
|=======================

See link:autoupgrade.adoc[Oracle AutoUpgrade] for details.

IMPORTANT: The gold image is built by Oracle on request. +
When no suitable image is cached, the download can take a few hours.

IMPORTANT: The name of the gold image must match `imagename` of `db26_si_ee` in `inventory/group_vars/all/db-homes.yml`. +
Change `imagename`, when AutoUpgrade downloaded a newer Release Update.

.Check the downloaded gold image on the VM
----
ls -l /u01/sw/db_home_*.zip
----

.inventory/group_vars/all/db-homes.yml
----
  db26_si_ee: &db26_si_ee
    version: 26.1.0.0
    oracle_home: /u01/app/oracle/product/db26_si_ee
    edition: EE
    imagename: db_home_26.04.zip
----

=== Install database with Ansible

.Start installation
----
cd ~/git/ansible-oracle/example/beginner/ansible
ansible-playbook playbooks/do_all.yml
----

NOTE: The execution takes approx. 60 minutes plus the download of the gold image.

.Configuration of the database
[options="header"]
|=======================
|Parameter |Value
|ORACLE_BASE |`/u01/app/oracle`
|ORACLE_HOME |`/u01/app/oracle/product/db26_si_ee`
|ORACLE_SID |`DB1`
|PDB |`ORCLPDB`
|db_create_file_dest |`/u02/oradata`
|db_recovery_file_dest |`/u02/fra`
|Listener |`LISTENER`, port 1521
|=======================

=== How to work with the installed database

.Login into the VM
----
ssh ol@192.168.66.161
----

.Switch to user oracle
----
sudo -iu oracle
----

.Initialize ocenv to set the environment variables
----
ocenv
----

`ocenv` shows the ORACLE_HOMEs, databases and listeners on the host.
`envhelp` shows an overview of the commands.

.Set ORACLE_SID
----
DB1
----

.Start SQL*Plus
----
sql
----
