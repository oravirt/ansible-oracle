== Oracle Restart Guide

This guide installs Oracle Restart 26ai and an Oracle AI Database 26ai with a container database `DB1` and the PDB `ORCLPDB`
in ASM on an Oracle Linux 9 VM with `ansible-oracle`.

AutoUpgrade downloads the _gold images_ of Oracle Restart (Grid Infrastructure) and of the database from My Oracle Support.

The guide is based on the link:beginner.adoc[Beginners Guide].
Steps that are identical are referenced and not repeated.

See link:restart_rac.adoc[Setup of Oracle Restart and Grid Infrastructure] for the details of Oracle Restart in `ansible-oracle`.

IMPORTANT: The example is made for a Hyper-V VM (Generation 1) created with `packer-hyperv`.
It finds the system disk and the ASM disk with Hyper-V specific paths, not with `/dev/sda` or `/dev/sdb`.
Read <<Disks of the VM>> before you use the example, especially with another hypervisor or another disk layout.

==== What are we going to do?

. Prepare the Ansible controller: Ansible in Ubuntu on WSL2 on Windows.
. Create an Oracle Linux 9 VM with a 2nd disk for ASM on Hyper-V.
. Configure the inventory with the IP address and login user of the VM.
. Start the playbook `playbooks/do_all.yml`. It executes all needed playbooks:
.. `opitzconsulting.ansible_oracle.os`: prepare the VM
.. `playbooks/asm_disk.yml`: split the 2nd disk into 2 partitions for the disk groups `DATA` and `FRA`
   and create the ASM devices with udev
.. `playbooks/autoupgrade.yml`: install AutoUpgrade on the VM and download the gold images of Oracle Restart and of the database
.. `opitzconsulting.ansible_oracle.swgi`: install Oracle Restart from the gold image, configure
   ASM with the disk groups `DATA` and `FRA` and the listener `LISTENER`
.. `opitzconsulting.ansible_oracle.swdb`: install the ORACLE_HOME of the database from the gold image
.. `opitzconsulting.ansible_oracle.manage_db`: create the database in ASM, registered in Oracle Restart

=== Requirements

==== Oracle Linux 9 VM

A VM with the requirements of the link:beginner.adoc#_oracle_linux_9_vm[Beginners Guide] is needed, with the following differences:

.Differences to the Beginners Guide
[options="header"]
|=======================
|Item |Requirement

|Disk 1 |System disk with the volume group `ol` on partition 3.

==== Disks of the VM

The example expects exactly 2 disks in a Hyper-V VM of Generation 1:

.Disks expected by the example
[options="header" cols="1,2,3,3"]
|=======================
|Disk |Hyper-V |Path in the VM |Used for
|System disk
|IDE controller 0, location 0
|`/dev/disk/by-path/acpi-VMBUS:01-vmbus-00000000000088990000000000000000-lun-0`
|Volume group `ol` on partition 3: swap and `/u01` (`host_fs_layout` in `group_vars/all/host.yml`)
|2nd disk
|SCSI controller 0, location 0
|`/dev/disk/by-path/acpi-VMBUS:01-vmbus-<id of the SCSI controller>-lun-0`
|ASM: partitions `data1` and `fra1` (`playbooks/asm_disk.yml`)
|=======================

===== Why not /dev/sda and /dev/sdb?

Hyper-V detects the IDE controller and the SCSI controller of a VM in parallel.
The device names depend on the order of the detection and can change with every new VM:

.Example: 2 VMs created with the same command
[options="header"]
|=======================
|VM |System disk |2nd disk
|1st VM |`/dev/sda` |`/dev/sdb`
|2nd VM |`/dev/sdb` |`/dev/sda`
|=======================

WARNING: With fixed device names, the playbooks would partition the wrong disk.
`orahost` creates a partition on the device of `host_fs_layout`, when its `pvname` does not exist.

Therefore the example uses paths, that do not depend on the order of the detection:

* *System disk*: IDE controller 0 has the fixed VMBus id `00000000-0000-8899-0000-000000000000` in every Hyper-V VM of Generation 1.
  The path is set in `hyperv_system_disk` in `group_vars/all/host.yml`.
* *ASM disk*: the id of the SCSI controller is new for every VM.
  `playbooks/asm_disk.yml` finds the disk itself: it is the only path `/dev/disk/by-path/acpi-VMBUS:*-vmbus-<id>-lun-0`,
  that is not on IDE controller 0.
  The playbook stops, when it finds no disk or more than 1 disk on the SCSI controller.
  `asm_disk_device` in `group_vars/all/asm.yml` is empty for this.

.Check the disks on the VM
----
lsblk -o NAME,SIZE,TYPE
ls -l /dev/disk/by-path/
----

.Example
----
NAME   SIZE TYPE
sda     50G disk
sdb    130G disk
...
acpi-VMBUS:01-vmbus-00000000000088990000000000000000-lun-0 -> ../../sdb
acpi-VMBUS:01-vmbus-c0b75e5252b24f7b9a989844d2250e0e-lun-0 -> ../../sda
----

`playbooks/asm_disk.yml` shows the ASM disk it uses:

----
ASM disk: /dev/disk/by-path/acpi-VMBUS:01-vmbus-c0b75e5252b24f7b9a989844d2250e0e-lun-0 => /dev/sda
----

===== Other VMs: what to change

Change the inventory, when your VM is not a Hyper-V VM of Generation 1 with exactly these 2 disks,
e.g. VirtualBox, KVM, VMware, a Hyper-V VM of Generation 2 or more than 1 disk on the SCSI controller.
Use a stable path from `/dev/disk/by-id/` or `/dev/disk/by-path/` of your VM, not `/dev/sdX`.

.Variables for other VMs
[options="header" cols="2,2,4"]
|=======================
|Variable |File |Change

|`hyperv_system_disk`
|`group_vars/all/host.yml`
|Stable path of the system disk. `host_fs_layout` uses `<hyperv_system_disk>-part3` as physical volume of the volume group `ol`.
Change `pvname` in `host_fs_layout` as well, when the volume group is not on partition 3,
e.g. `{device: /dev/disk/by-id/wwn-0x..., pvname: /dev/disk/by-id/wwn-0x...-part2}`.

|`asm_disk_device`
|`group_vars/all/asm.yml`
|Stable path of the ASM disk, e.g. `/dev/disk/by-id/wwn-0x...`.
Mandatory, when the VM is not a Hyper-V VM: the automatic detection works with the VMBus of Hyper-V only.
|=======================

TIP: Check the paths with `ls -l /dev/disk/by-id/ /dev/disk/by-path/` on the VM before the 1st execution of the playbooks.
`playbooks/asm_disk.yml` partitions the ASM disk only, when it is empty, and stops otherwise.

==== Create the VM with Hyper-V and Packer

Build the Oracle Linux 9 template as described in
link:beginner.adoc#_create_the_vm_with_hyper_v_and_packer[Create the VM with Hyper-V and Packer] of the Beginners Guide.

IMPORTANT: All steps in this chapter are executed in PowerShell on Windows, not in WSL.

`create-vm.ps1` adds the 2nd disk with `-DataDiskGB`.
`-StartupMemoryGB 12 -MemoryGB 6` gives the VM 12 GB memory from the start
(maximum of the dynamic memory: `max(2 x MemoryGB, StartupMemoryGB)`).

.Create the VM from the template
----
cd OL9
.\create-vm.ps1 -NewVMName restart -Hostname restart -ExternalSwitch intern_66 -FixedIP 192.168.66.171 `
    -CPUs 2 -StartupMemoryGB 12 -MemoryGB 6 -DataDiskGB 50
----

The 2nd disk is connected to the SCSI controller of the VM.
At the end, `create-vm.ps1` shows the block devices of the VM (`lsblk`).

IMPORTANT: The 2nd disk can be `/dev/sda` or `/dev/sdb` in the VM, see <<Disks of the VM>>.

IMPORTANT: Increase the system disk of the VM, e.g. to 130 GB, before you start the installation
(see the link:beginner.adoc#_create_the_vm_with_hyper_v_and_packer[Beginners Guide]).

=== Configure inventory

==== IP address and login user

The VM is configured in `inventory/hosts.yml`.
Change `ansible_host` and `ansible_user` for your VM.

.inventory/hosts.yml
----
---
all:
  children:
    has:
      hosts:
        restart:
          # IP address or DNS name of the Oracle Linux 9 VM
          ansible_host: 192.168.66.171
          # Login user on the VM with sudo privileges (SSH key login)
          ansible_user: ol
----

NOTE: `restart` is only the name of the host in the inventory.
The host specific variables are in `inventory/host_vars/restart/`.
Rename the directory as well, when you change the name.

==== ASM disk

`playbooks/asm_disk.yml` prepares the 2nd disk of the VM for ASM before the installation of Oracle Restart:

. It splits the disk into 2 GPT partitions.
. It creates the udev rule `/etc/udev/rules.d/99-oracle-asm.rules`.
  The rule creates a symlink in `/dev/oracleasm` for each partition and sets owner, group and mode for ASM.

.Partitions and ASM devices
[options="header"]
|=======================
|Partition |Name |Size |ASM device |Owner |Disk group
|1 |`data1` |50% (25 GB) |`/dev/oracleasm/data01` |`oracle:asmadmin`, `0660` |`DATA`
|2 |`fra1` |50% (25 GB) |`/dev/oracleasm/fra01` |`oracle:asmadmin`, `0660` |`FRA`
|=======================

The udev rule uses the name of the GPT partition (`ID_PART_ENTRY_NAME`), not the device name of the disk.
The ASM devices stay the same, even when the disk gets another device name.

The playbook partitions the disk only, when it is empty (no partition table, no filesystem, no ASM header).
Otherwise it stops with an error.

.inventory/group_vars/all/asm.yml (extract)
----
asm_disk_device: ""

device_persistence: ''
partition_devices: false
oracle_asm_disk_string: /dev/oracleasm/*
oracle_asm_init_dg: data

asm_diskgroups:
  - diskgroup: data
    ...
    disk:
      - {device: /dev/oracleasm/data01, asmlabel: data01}
  - diskgroup: fra
    ...
    disk:
      - {device: /dev/oracleasm/fra01, asmlabel: fra01}
----

* `device_persistence: ''`: `ansible-oracle` uses the devices from `asm_diskgroups` as they are.
  The devices must exist with owner `oracle` and group `asmadmin` before the installation of Oracle Restart.
* `partition_devices: false`: `ansible-oracle` does not partition the devices.

`asm_disk_device` is empty: `playbooks/asm_disk.yml` finds the disk on the SCSI controller of the Hyper-V VM.
See <<Disks of the VM>> for the details and the changes for other VMs.

NOTE: The ASM Filter Driver (`device_persistence: asmfd`) is desupported with Oracle AI Database 26ai.

The disk group `data` (`oracle_asm_init_dg`) is created by `root.sh` during the configuration of Oracle Restart
and contains the SPFile of ASM.
The disk group `fra` is created afterwards by the role `oraasm_manage_diskgroups`.

=== AutoUpgrade and gold images

AutoUpgrade is executed on the VM and downloads the gold images into `/u01/sw`,
as described in link:beginner.adoc#_autoupgrade_on_the_vm[AutoUpgrade on the VM] of the Beginners Guide.

This guide downloads 2 gold images:

.Download configuration in inventory/group_vars/all/autoupgrade.yml
----
autoupgrade_download_patches:
  - target_version: 26
    patch: "RU:{{ example_ru_26 }},MRP,AHF,CVU"
    gold_image: "ALL"
    platform: LINUX.X64
  # Gold Image of Grid Infrastructure for Oracle Restart
  - target_version: 26
    patch: "GI:{{ example_ru_26 }},MRP"
    gold_image: "ALL"
    platform: LINUX.X64
----

The role `autoupgrade` renames the gold images and creates a symlink to the latest gold image of each release
(`autoupgrade_download_gold_image_rename: true`, `autoupgrade_download_gold_image_latest: true`).

.Check the downloaded gold images on the VM
----
ls -l /u01/sw/db_home_*.zip /u01/sw/gi_goldimage_*.zip
----

.Example
----
db_home_26.04.zip
db_home_26_latest.zip -> db_home_26.04.zip
gi_goldimage_26_04.zip
gi_goldimage_26_latest.zip -> gi_goldimage_26_04.zip
----

The inventory uses the symlinks:

[options="header"]
|=======================
|Gold image |Variable |File
|Oracle Restart |`oracle_install_image_gi` in `group_vars/all/restart.yml` |`gi_goldimage_26_latest.zip`
|Database |`imagename` in `group_vars/all/db-homes.yml` |`db_home_26_latest.zip`
|=======================

IMPORTANT: The version of the database home must not be newer than Oracle Restart.
Both gold images are downloaded with the same release update (`example_ru_26` in `group_vars/all/oracle_ru.yml`).

TIP: Use the real filenames, e.g. `gi_goldimage_26_04.zip`, when Oracle Restart must be installed with a fixed release update.

=== Oracle Restart

.inventory/group_vars/all/restart.yml
----
oracle_install_option_gi: HA_CONFIG
oracle_install_version_gi: 26.1.0.0

oracle_install_image_gi: gi_goldimage_26_latest.zip
oracle_home_gi: /u01/app/oracle/product/gi26_restart

apply_patches_gi: false
patch_before_rootsh: false

role_separation: false
----

* `oracle_install_option_gi: HA_CONFIG` configures Oracle Restart.
* `oracle_install_version_gi` is the base release, not the release update of the gold image.
* `oracle_home_gi` must be below `grid_base` (default for Oracle Restart: `oracle_base`, `/u01/app/oracle`).
* `apply_patches_gi: false`: the gold image contains the release update.
* `role_separation: false`: Oracle Restart is installed and owned by `oracle`.

The listener `LISTENER` runs in the ORACLE_HOME of Oracle Restart (`use_gi_home: true` in `group_vars/has/listener.yml`).

See link:restart_rac.adoc#_oracle_restart[Oracle Restart] for all variables.

=== Install Oracle Restart and database with Ansible

.Start installation
----
cd ~/git/ansible-oracle/example/restart/ansible
ansible-playbook playbooks/do_all.yml
----

NOTE: The execution takes approx. 90 minutes plus the download of the gold images.
